**只读策略（vendor `adapter-common::open_source_db_readonly`，0002 patch）**：

1. 一律 `SQLITE_OPEN_READONLY`（无 CREATE）——依赖 flags 本身保证只读，不靠"没有 INSERT"推断；
   源库不存在时 open 直接报错（绝不自动创建空库）。
2. **无 `-wal`/`-shm` sidecar**（库已被属主 checkpoint）→ 以 `immutable=1` URI 打开：
   零 sidecar 创建、零锁、零 journal。正确性依据：无 sidecar 的 WAL 库已完成 checkpoint，
   文件处于静态。
3. **有 sidecar**（属主进程活着）→ 普通只读打开：可见 WAL 内已提交数据；sidecar 已存在，
   采集不新建任何文件。
4. 打开后统一 `set_busy_timeout(2000ms)`——锁定场景在预算内以 `DatabaseError` 诊断跳过，
   绝不无限阻塞 UI 或未来 worker。
5. 检查 sidecar 与 open 之间存在竞态窗口（写入方恰在此刻启动）；Phase 1 的短读可接受，
   完整并发策略归 Phase 3 worker supervisor。
6. 读路径零 PRAGMA、零 migration、零 VACUUM/ATTACH；测试断言采集前后源库 SHA-256 不变。

## 7. patch 文件 whitespace 治理

0002 patch 以 `-U3` 生成并做了空上下文行净化（嵌入 diff 中仅含单空格的空上下文行改为
真正的空行——GNU patch 按惯例视为空上下文），使 `git diff --check` 不再报"行尾空白"。
剩余的 "space before tab in indent" 提示来自嵌入 diff 忠实保留的上游 tab 缩进 JSON 字节
——它们是 patch 数据本身的字节，不可"修复"；已通过 `.gitattributes`
（`src-tauri/vendor/ccusage/patches/*.patch -whitespace`）让 git 将 patch 文件视为
whitespace 有意义的数据文件，`git diff --check` 现为 0。
