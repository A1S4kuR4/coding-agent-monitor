## Native acceptance and release decision

**PARTIAL / NOT READY FOR PUBLICATION.** The user requested a status summary
and continuation prompt before the remaining native gates were finished.

Completed native evidence (isolated synthetic data, release executable):

- GUI starts with a restricted child PATH containing Windows/System32 only;
  no Node/pnpm/Cargo is on that process PATH. This is not a clean-OS claim.
- English dark-theme default view; on-demand thirty-day range has exactly the
  expected 2026-08-12 through 2026-09-10 dates; today's aggregate stays unchanged.
  Selected-day and model/token details are present in the native WebView2 tree.
- Making the isolated preference temp path a directory causes a real disk
  write failure. UI retains English and shows the save error; the old file is
  unchanged. Removing the fault and retrying saves zh-CN and switches the UI.
- Close acknowledgement persists and hides the window. A second executable
  launch exits with code 0 and restores the one existing main process.
- Found the scrolled close-notice visibility defect and fixed it in `6b6f9db`.
  Unit coverage checks scrolling/focus and repeat requests; native revalidation
  of the fixed notice was not finished before the requested handoff.
- Final executable was launched with the prior synthetic snapshot and an
  invalid Claude source. Snapshot file SHA-256 remained identical after the
  failed refresh. Final GUI freshness/error presentation was NOT VERIFIED:
  Computer Use bindings reset when the user requested the handoff.
- Synthetic 100,000-line Claude benchmark, 30 fresh worker runs per range:
  seven-day p50/p95 231.92/256.35 ms, peak working set 78.75 MiB; thirty-day
  p50/p95 234.04/247.08 ms, peak 78.73 MiB; both CPU median 218.75 ms.
  Source is 25,977,780 bytes over 60 days; output row counts and diagnostics
  asserted. This is one-source worker evidence, not all-agent native UI memory.

Isolation and cleanup:

- Startup initially failed because the synthetic Windows profile omitted its
  AppData folders (`filesystem_error: unknown path`). Creating isolated
  Roaming/Local directories fixed the harness; this was not a product fix.
- Original application data was backed up before testing and has been restored
  byte-for-byte with SHA-256 checks. The successful native runs use their own
  synthetic HOME/USERPROFILE/AppData/WebView directories. Real autostart
  registration was not changed by the GUI tests.
- Agent-owned native processes were force-stopped for restart testing/cleanup.
  This does NOT establish graceful tray Exit behavior. At handoff a separate
  executable under `D:/DevTools/test/Coding Agent Monitor/` was running; it was
  not started by this acceptance helper and was left untouched.
- Local test harness, logs, synthetic fixtures and backup hashes remain in
  ignored `.scaffold-root/v040-evidence/`. Never commit those private backups.
