# v0.3 Phase 4B — 生产采集切换到单 EXE Batch Worker

日期：2026-08-31 · 基线：Phase 4A 最终实测 Gate（`d09e9d1`）
前置证据：`docs/V0.3_PHASE4A_FINAL_GATE.md`（17-Agent 非空 shadow 17/17 PASS；
release-to-release 相对 Gate PASS 0.49–1.23 ≤ 1.25；体验 Gate PASS p95 ≤ 134 ms）。

## 1. 生产调用链（已切换）

```text
之前（v0.2，Phase 4A 及以前）：
  get_usage_summary → sidecar::collect_usage → ccusage.exe + ccusage-antigravity.exe
                    → normalize_reports → UsageSummary

现在（v0.3 Phase 4B）：
  get_usage_summary → worker_runner::collect_usage()
                    → worker_runner::collect_snapshot（single-flight + 2s 结果缓存）
                    → 一次 batch snapshot worker（current_exe + --cam-internal-collector-worker-v1）
                    → normalize_snapshot → UsageSummary（公共契约不变）
```

变更文件：

| 文件 | 变更 |
| --- | --- |
| `src/commands/usage.rs` | `get_usage_summary` 改调 `worker_runner::collect_usage()`；不再引用 sidecar |
| `src/tray/mod.rs` | 托盘后台刷新改调同一 `worker_runner::collect_usage()`（与手动刷新共享同一 single-flight） |
| `src/collector/worker_runner.rs` | 新增生产入口 `collect_usage()` 与 `production_snapshot_request()`（全部 17 Agent、Environment 源、today-6..=today 本地窗口、系统 IANA 时区、`prod-<millis>` request_id） |
| `src/error.rs` | `From<CollectorError> for AppError`（脱敏 display 消息；前端只消费 message，v0.2 一致） |
| `src/shutdown.rs`（新） | 共享 shutdown 标志；supervisor 与 sidecar runner 共同 gate，生产链不再引用 sidecar 模块 |
| `src/sidecar/runner.rs` | shutdown 标志改为委托 `shutdown` 模块；sidecar 代码与二进制全部保留（Phase 5 删除） |
| `Cargo.toml` | 新增直接依赖 `jiff 0.2.35`（与 vendored 引擎同版本同 features；仅用于读取系统 IANA 时区，不改变依赖闭包） |

**生产路径禁止项验证**：不调用 sidecar runner、不检查 sidecar 文件、不 spawn ccusage、
worker 失败时**无任何 fallback**（见 §5）。

## 2. 请求构造（生产形状）

- **Agents**：`AgentKind::ALL` 全 registry，确定性顺序，`DataSourceV1::Environment`
  （vendored 引擎按进程环境解析默认目录，与 CLI 行为一致）。
- **窗口**：today-6 ..= today（本地日期，两端含），与 v0.2 sidecar `--since` 边界一致。
- **时区**：`jiff::tz::TimeZone::try_system()` → IANA 名；无法解析时传 `"system"` 标记
  （vendored 引擎对该名回退到自身系统时区，与父进程 `chrono::Local` 的 today 一致）。
- **request_id**：`prod-<Utc millis>`；supervisor 校验响应回显一致。

## 3. Partial failure 与缓存策略（实现+测试钉死）

| # | 场景 | 行为 |
| --- | --- | --- |
| 1 | Environment 源、Agent 未安装/默认目录不存在/无数据 | 正常 empty success；不阻断其他 Agent；**不制造零记录 Agent**（`production_refresh_with_no_agents_installed_is_an_empty_success` 等） |
| 2 | 用户显式设置的环境变量指向无效位置（如 CLAUDE_CONFIG_DIR 无效） | 该 Agent `SourceUnavailable` → **整次刷新失败**（v0.2 一致：sidecar 失败=刷新失败）；前端保留旧数据 |
| 3 | 单 Agent 可恢复损坏（跳过损坏记录/文件） | 数据存活，diagnostic 不进入 UsageSummary（schema 不表达，与 v0.2 sidecar 路径一致，该路径从未感知 diagnostic） |
| 4 | 单 Agent 不可恢复（DB 错误/VendorAdapter） | 结构化 per-agent error → `normalize_snapshot` 整次失败；runner 缓存失败 2s；UI 保留旧结果；无缓存则返回稳定错误 |
| 5 | worker panic（整批 fatal） | fatal Internal 响应 → 整次刷新失败；**不发布可能少计的部分快照**；缓存失败后下次刷新恢复（`production_worker_panic_fails_whole_refresh_then_recovers`） |
| 6 | worker timeout / cancel / shutdown race | 整次刷新失败（Timeout/Cancelled）；不使用部分结果；无残留 PID（`production_shutdown.rs`） |
| 7 | 协议错误 / 版本不匹配 / request_id 不匹配 | supervisor `Protocol` → 整次刷新失败（Phase 3 既有测试 + 生产映射） |
| 8 | 新鲜缓存（≤2s） | 共享缓存结果（成功或失败），不启动新 worker；20 并发共享（`production_twenty_concurrent_public_refreshes_share_one_worker`） |
| 9 | shutdown 后新刷新 | 拒绝新 worker（`shutdown_mid_refresh_..._refuses_new_workers`） |
| 10 | 进程安全 | 仅 kill supervisor 自己创建并持有 handle 的 child（`kill_and_wait`）；无按名/路径枚举杀进程；回归测试 `supervisor_timeout_kills_only_the_supervised_worker`：无关 CAM 进程在 supervisor timeout 后存活 |

**单缓存原则**：生产链只有一个缓存（`collect_snapshot` 的 snapshot 结果缓存，成功与失败
均缓存 2s，与 v0.2 `RESULT_FRESH_FOR` 一致）；`normalize_snapshot` 每次调用独立执行
（<1 ms），不在 command 层建第二套缓存。

## 4. 批准的 v0.3 值语义变化（已生效 + snapshot 测试）

1. **reasoning 分类**：来源明确的 reasoning/thinking 进入 `reasoningTokens`，不再计入
   `unclassifiedTokens`；total 不变。snapshot：`production_refresh_reasoning_semantics_on_public_contract`
   （codex 1320 = 900+200+100 四桶 + reasoning 20 + unclassified 100；v0.2 为 0/120）。
2. **缺价语义**：unpriced-only 记录 → 该日 `estimatedCostUsd: null` + missing-pricing
   状态（**不伪造 $0.00**；v0.2 sidecar 会伪造 0.0）。**mixed priced/unpriced 日 → null**
   （vendor 的 totalCost 是只含已定价模型的误导性部分和；`normalize_snapshot` 现在按
   `models_missing_pricing` 判定成本不完整）。snapshot：
   `production_refresh_unpriced_only_agent_has_null_day_cost`、
   `production_refresh_mixed_priced_and_unpriced_day_cost_is_null`。
3. **UsageSummary JSON schema 完全不变**：字段、camelCase、排序、cache share、
   Agent id/displayName、today/last7 结构零改动；`sidecar_shadow`、`shadow17`、
   collector golden 全部继续通过（shadow17 对 mixed 日的差异按本批准文档化）。

## 5. 生产不再调用 sidecar 的证据

1. **poison marker（运行时）**：在 sidecar runner 的 packed 查找路径（current_exe 目录）
   放置无法执行的伪 `ccusage.exe`/`ccusage-antigravity.exe`，生产刷新照常成功
   （`production_chain_never_executes_a_sidecar_poison_marker`）——任何 fallback 都会
   在该路径失败。
2. **进程观测（运行时）**：生产刷新期间以 10ms 频率枚举进程，无任何 `ccusage*` 进程
   （`no_ccusage_process_appears_during_production_refresh`）；release 手工验证同样
   零 ccusage（§6）。
3. **静态审计**：`production_chain_source_has_no_sidecar_runner_references` 扫描生产链
   全部源文件（command/tray/worker_runner/supervisor/worker/ccusage facade/shutdown），
   断言不含 sidecar runner 符号（`sidecar::collect_usage`、`sidecar_paths`、
   `ccusage.exe`、`UNIFIED_ARGS` 等）。
4. **release 手工移走 sidecar**：`target/release/` 下两个 sidecar 副本重命名后，release
   应用启动刷新仍产生正常 worker（§6）。
5. sidecar 源码与二进制**保留**供 shadow/回滚（Phase 5 删除）；保留≠可 fallback。
