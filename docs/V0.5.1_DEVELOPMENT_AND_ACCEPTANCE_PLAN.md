# Coding Agent Monitor v0.5.1 开发与验收计划

**状态（2026-09-25）：** 本地候选，尚未发布。已发布基线是远端 `main` 的
`6f86eb1`（v0.5.0）；候选源码的三份产品版本清单已改为 `0.5.1`。本计划规定
v0.5.1 的变更和验收口径，不把本地改动或旧版测试自动记为通过。实际证据记录在
[v0.5.1 验证记录](V0.5.1_RELEASE_VERIFICATION.md)。

## 范围与决定

1. **成功采集的文本收敛。** 用户于本轮明确选择：成功采集虽含可恢复的跳过记录，
   前端也完全隐藏“覆盖可能不完整”提示。主界面的覆盖横幅、30 日元信息及选中日
   详情中的覆盖说明都不再显示。Rust 与 TypeScript 公共 `UsageSummary` 的
   `coverage` / `diagnostics` 数据仍保留，供诊断和后续核对使用。这是 **v0.5.1
   新产品决定**；v0.4 计划要求在主界面标注覆盖风险，v0.5.0 验收按当时行为记录，
   两者均为历史文件，不回写。可恢复跳过发生时，成功总量只包括已接受记录，
   因此可能低于完整本地用量；发布说明须披露这一限制。
2. **补充离线参考价格。** ccusage 解析器仍是 v20.0.20；以固定提交和 SHA-256
   刷新 LiteLLM 与 models.dev 派生价格表，新条目优先，旧版独有模型 ID 留存。
   LiteLLM 条目从 3,039 增至 4,509，models.dev 条目从 2,275 增至 3,164。
   来源、许可证与生成规则见[价格维护说明](PRICING_MAINTENANCE.md)和
   [`pricing-manifest.json`](../src-tauri/vendor/ccusage/pricing/pricing-manifest.json)。
   重点价格断言核对 GPT-5.6 Sol、GPT-6 Sol、Claude Opus 5.5 与 Gemini 3.8 Flash
   的公开参考价。仍缺价的模型（包括部分 Antigravity 内部变体）保持成本不可用，
   不能填零或声称已覆盖全部模型。
3. **保持既有成本口径。** 价格随安装包固定，运行时不联网更新。金额是公开 API
   单价下的参考估算，不是账单、订阅、credits 或历史成交价；用新版本重新计算
   旧日志，历史估算也可能变化。任一贡献模型缺价时，完整成本仍为 `null`，
   不展示有价部分小计作为总额。结构化 Agent 失败仍使本次采集整体失败，旧快照的
   失败/过期标注继续可见。

本轮不增加 Agent、账户额度、云服务、运行时价格请求或新的产品页面。

## 验收门禁

| 项目 | 必须核对的行为与证据 |
| --- | --- |
| 成功页文案 | 中英文、7/30 日、30 日周/日视图和选中日详情中，含可恢复跳过诊断的成功快照不显示覆盖提示；普通成功、无用量与缺价文案仍正确。用合成数据验证，不将 fixture 称作真实用量。 |
| 失败与诊断契约 | Rust/TypeScript 公共摘要仍含脱敏的 `coverage` / `diagnostics`；结构化来源失败、刷新失败、旧日或过期快照仍按原规则处理，不能把失败伪装为成功零值。 |
| 价格与成本 | 固定来源提交、文件哈希、许可证、旧键保留和可重建性可核对；主流模型参考单价有聚焦测试；缺价与真实零有区分，混合缺价总成本为未知；不在启动或构建时获取浮动在线价格。 |
| 自动检查 | 按改动范围记录 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm test:e2e`、`pnpm vendor:verify`、`pnpm build`、`cargo check --manifest-path src-tauri/Cargo.toml`、`cargo test --manifest-path src-tauri/Cargo.toml`、vendor Cargo 测试及 `pnpm tauri build` 的实际结果；失败和未运行分别保留。 |
| Windows 发布包 | 从确定的源码 SHA 干净构建，核对 MSI/NSIS 版本、负载、同一 EXE worker、安装/升级/卸载与托盘基本行为；记录包大小、SHA-256 和签名状态。原生 UI 与外部主机覆盖项按本次实际执行记录。 |

每项仅在 [v0.5.1 验证记录](V0.5.1_RELEASE_VERIFICATION.md)写入本轮证据后才可
标为 `PASS`。`NOT RUN`、失败和发布者接受的覆盖缺口不得写成技术通过；v0.5.0
的测试、豁免与发布决定不能转移为 v0.5.1 的结果。发布时核对候选源码、安装包
哈希、Release 文案与公开资产一致，再更新状态索引。
