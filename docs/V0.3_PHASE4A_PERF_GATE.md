| 来源 | 影响 | 可否优化 |

## Gate 决策

### 相对性能 Gate（median ≤ sidecar 合计的 125%）

**当前状态：未通过**（debug 7.13×，release 预计约 3×）。

### 体验目标（p95 ≤ 1 秒）

**当前状态：通过**（debug p95 = 213 ms；release 预计更低）。

### 建议

**推荐：接受 one-shot worker 的绝对延迟，暂不实施常驻 worker。**

理由：
- worker p95 < 1 秒（实测 debug 213 ms，release 预计 < 150 ms），远低于
  2 分钟自动刷新间隔（120,000 ms）的 0.2%；
- 手动刷新延迟 < 150 ms，用户几乎无感；
- one-shot worker 每次启动干净进程，无 stale pricing/state/内存泄漏风险；
- 常驻 worker 需要解决 crash 恢复、多请求 framing、idle 管理、协议错配、
  升级兼容和故障隔离降低等架构问题，收益不成比例；
- 7.13× 相对差异主要由进程冷启动成本驱动，不是采集逻辑本身慢。

### 替代方案比较

| 方案 | 延迟 | 复杂度 | 故障隔离 | 推荐 |
| --- | --- | --- | --- | --- |
| 接受 one-shot worker 绝对延迟 | <150 ms (release) | 已实现 | ✅ 每次干净进程 | ✅ |
| 继续优化启动/初始化 | 可能降至 ~100 ms | 中（需 profiling） | ✅ | 可选 |
| 常驻 worker 架构变更 | ~0 ms（复用进程） | 高（framing/crash/idle/升级） | ❌ 降低 | ❌ 另立任务 |

### 正式决策

相对性能 Gate **未通过**（7.13× > 1.25×）。但绝对 p95 **远低于 1 秒**，
形成本 waiver 材料。**Phase 4B 切换保持阻塞**，等待产品负责人审批本 waiver
或要求进一步优化。在获得批准前，生产 command 仍使用 sidecar。
