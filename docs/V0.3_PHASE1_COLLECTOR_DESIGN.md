# v0.3 Phase 1 — 内部 Collector API 设计与实现记录

日期：2026-08-30（完成版）· 对应计划：`docs/V0.3_DEVELOPMENT_AND_ACCEPTANCE_PLAN.md` Phase 1。

本版覆盖 Phase 1 全部验收范围：全 Agent registry、per-agent 隔离、参数化路径、结构化
diagnostics、版本化 V1 协议、语义测试与 golden parity。生产 sidecar 路径仍未切换。

## 职责边界

`src-tauri/src/collector/` 是 CAM 代码与 vendored ccusage 源码之间**唯一**的接触点：

- **入方向**：上层只使用 CAM 自有类型（`Collector` trait、`CollectRequest`/`CollectResult`、
  `UsageRecord`/`ModelBreakdown`、`AgentKind`、`CollectorError`）。公共签名不含
  `ccusage_*` crate 类型、`serde_json::Value`、CLI argv 或 stdout 契约。
- **出方向**：`collector::ccusage::AgentCollector` 调用 vendored seam
  `ccusage_adapter_all::daily_report_json_by_agent`（Gate 0 PoC 入口），并在适配层内把 vendor JSON
  转成统一类型。上层禁止依赖 vendor JSON schema。
- **不改变生产路径**：生产采集仍走 `src-tauri/src/sidecar` 的 ccusage sidecar 可执行文件；
  本 API 目前仅被契约测试调用。Phase 2 才切换调用链。

## 核心类型与字段语义

| 类型 | 语义 |
| --- | --- |
| `AgentKind`（= `CollectorKind`） | 采集目标 agent；`id()` 给出 vendor 统一报告里的 agent id（`claude`/`antigravity`），`label()` 为显示名 |
| `CollectWindow` | 日期粒度窗口，**两端均为闭区间（inclusive）**；`new()` 拒绝倒置区间 |
| `TimeZoneSpec` | IANA 时区名（传给 vendor 做 daily 分桶）；请求默认 `utc()` |
| `DataSource` | Phase 1 仅 `Environment`：按 vendor CLI 同样的进程环境变量（`CLAUDE_CONFIG_DIR`、`ANTIGRAVITY_DATA_DIR`…）解析各 agent 数据根 |
| `CollectRequest` | `agent` + 可选 `window` + `timezone` + `source`；agent 与 collector 不匹配 → `InvalidRequest` |
| `UsageRecord` | **每个 agent 每天一条聚合记录**（vendor 可靠提供的粒度；session 级留作后续扩展）。字段：date、agent、input/output/cache_creation/cache_read/total_tokens（全部 `u64`）、`cost: Option<CostNanoUsd>`、`models_used`（排序去重）、`model_breakdowns`（按模型名排序）、`models_missing_pricing`（排序） |
| `ModelBreakdown` | 每模型明细；`missing_pricing: bool` + `cost: Option<CostNanoUsd>` |
| `CostNanoUsd` | 固定点 **i128 纳米美元**（10⁻⁹ USD）。vendor 的 f64 成本只在适配层边界转换一次（round half-away-from-zero，非有限值→None）；下游只做整数运算。`Some(0)` 表示"有价格且计算结果为零"；`None` 表示"无定价/不可用"——绝不用 0 冒充缺价 |
| `CollectResult` | `agent` + `records`（按日期升序；空数据=成功空结果，不是错误） |

`#[non_exhaustive]` 用于 `UsageRecord`/`ModelBreakdown`/`CollectResult`/`CollectorError`/`DataSource`，
为后续字段演进留出空间。未知模型名以 `ModelName` 原样保留；未知 vendor 字段被适配层忽略
（forward-compatible），不阻塞采集。

## 错误分类（`CollectorError`）

| 变体 | 含义 |
| --- | --- |
| `InvalidRequest` | 请求无效（倒置窗口、agent 不匹配、未知 agent id、不支持的 DataSource、协议版本错误） |
| `SourceUnavailable` | 数据源根目录不存在或不是合法 agent 数据目录 |
| `CorruptData` | 数据存在但无法解析（当前 vendor 将可恢复损坏降级为 diagnostic，见下） |
| `DatabaseQuery` | SQLite 数据源打开/查询失败（不可恢复时） |
| `VendorAdapter` | vendored 引擎失败（loader 内部错误、输出形状不符） |
| `PricingUnavailable` | 定价数据本身不可用（单模型缺价**不是**错误，见 `cost: None` + diagnostics） |
| `Timeout` / `Cancelled` | 预留给 Phase 2/3 的取消与超时路径（当前同步实现不产生） |
| `Internal` | 不变量破坏等内部错误 |

**分类基于结构化错误种类，不依赖错误文本。** vendor 侧新增 `load_context::LoadFailureKind`
（`SourceUnavailable`/`InvalidConfig`/`Database`/`Internal`）：adapter 在失败点先写入结构化失败槽
（claude 根校验即此），`daily_report_for_agent` 优先消费结构化槽位，仅当槽位为空才落到
`VendorAdapter(Internal)`。早期版本依赖的 `"No valid … data directories"` 文案哨兵已移除；
该文案仍出现在给人类看的 `details` 中，但不参与分类。

错误 details 只包含简短原因描述，不含密钥、完整日志或用户文件内容；诊断的结构化 `file` 字段
仅记录**文件名**（不含完整路径），vendor 消息文本中的本地路径已被最小化处理。

## diagnostics 与 fatal error 的边界

- **可恢复 → `CollectResult.diagnostics`**（成功结果 + 结构化诊断，保留尽可能多的数据）：
  - `CorruptRecord`：单条记录损坏被跳过（claude 日期聚合/会话读取器的坏 JSON 行、
    不支持的 null 字段、不可解析时间戳）；
  - `CorruptFile`：整个源文件解析失败被跳过（amp/gemini/kimi/qwen/droid/codebuff/copilot/
    grok/openclaw/pi 等的 per-file 失败点）；
  - `DatabaseError`：SQLite 源打开/查询失败被跳过（antigravity/goose/hermes/kilo/opencode）；
  - `SourceUnreadable`：源存在但不可读。
- **不可恢复 → `CollectorError`**：数据根缺失/非法（`SourceUnavailable`）、配置非法
  （`InvalidRequest`）、引擎内部失败（`VendorAdapter`/`Internal`）。数据源完全不可用绝不
  伪装成空成功结果。
- 数值行为保持与 v0.2/上游一致：跳过不改变已计入数据的聚合结果，差异只通过 diagnostics
  表达，不擅自改聚合。
- 诊断不含原始日志、密钥或敏感内容；结构化 `file` 字段仅文件名。

## vendor 适配边界与最小扩展（0002 patch，可重放）

1. **`missingPricing` 序列化**（core `types.rs`）：上游在 `ModelBreakdown` 上
   `#[serde(skip_serializing)]`，统一 JSON 中"缺价"与"$0"同为 `cost: 0.0`，无法表达产品
   null/zero 契约。patch 使 model breakdown 序列化 `"missingPricing": true|false`。
2. **`load_context` 模块**（core）：load 域的结构化诊断收集器、结构化失败槽、per-load
   数据根覆盖。三者为进程级存储但在每次 load 开始时清空、结束时排空，且
   `daily_report_for_agent` 以互斥锁串行化 load —— 不是环境变量，不跨 load 泄漏。
3. **`daily_report_for_agent(agent, root_override, shared) -> AgentLoadOutcome`**
   （adapter-all）：只构建并执行目标 agent 的 load spec（其他 agent 的 loader 根本不会
   构造/运行），按 `AgentLoadOutcome::{Report{report,diagnostics}, SourceUnavailable, Failed}`
   结构化返回。`daily_report_json_by_agent`（全 agent PoC seam）保持不变，供 Gate 0 测试用。
4. **全 adapter 接线**：17 个 adapter 的路径解析器优先消费显式覆盖（再走环境变量/默认目录）；
   各 loader 的"Failed …"跳过点写入 `LoadDiag`；claude 日期/会话读取器的行级跳过点、
   antigravity 的 gen_metadata 查询失败点不再静默。
5. **`load_rows_filtered`**（loader）：spec 按名称过滤后再执行；未知 agent →
   `Failed(InvalidConfig)`。

CAM 侧类型转换全部在 `collector::ccusage` 完成；vendor JSON 形状与 vendor 类型不出现在
公共签名。

## 数据源路径规则

- `DataSource::Environment`（生产默认）：vendor 引擎按 CLI 同样的环境变量解析各 agent
  数据根。CAM 不修改任何环境变量。
- `DataSource::Paths(Vec<PathBuf>)`：显式数据根，逐字传给 vendor 的 load 域覆盖，解析与
  加载分离。路径布局必须与该 agent 的环境变量覆盖等价（如 claude=含 `projects/` 的配置根、
  codex=CODEX_HOME 形式的 home 列表）。
- 路径支持 Windows 非 ASCII、空格与长路径（vendor 侧仅做 `PathBuf` 传递与 `is_dir` 校验）；
  CAM 不写入、不迁移、不锁定 agent 源数据库（全部只读打开）。
- 错误与诊断不暴露不必要的完整用户路径（结构化 `file` 字段仅文件名）。

## V1 内部传输协议（`collector::protocol`）

纯数据类型 + serde derive；本阶段只实现与测试，不接 stdin/stdout、不 spawn 进程、不初始化 worker。

- `CollectorRequestV1`：`version`(=1)、`request_id`、`agent`(vendor id 字符串)、
  `window{start_inclusive,end_inclusive}`(YYYY-MM-DD，两端含)、`timezone`(IANA)、
  `source`(`{"kind":"environment"}` | `{"kind":"paths","roots":[…]}`)。
- `CollectorResponseV1`：`version`、`request_id`、`status`(`ok`|`error` flatten)。
  ok → `report{records,diagnostics}`；error → `error{code,message}`。
- `ErrorCodeV1` 与 `CollectorError` 一一对应（snake_case 字符串编码）。
- **精度**：token `u64` 与成本 `i128` 纳米美元一律编码为**十进制字符串**
  （`"input_tokens":"9223372036854775807"`、`"cost_nano_usd":"1234567891234567891234"`），
  超过 JS 2⁵³ 安全整数也零损失。
- **未知字段策略**：同版本内未知字段读取时忽略（向后兼容的增量演进）；字段增删/语义变化
  必须 bump `PROTOCOL_VERSION`，旧版本读取方按错误拒绝。
- **错误响应**：`message` 为 Display 级人类可读文本；不含 Rust Debug 串、调用栈或密钥。
- 域类型与协议类型互转：`CollectorRequestV1::into_domain()`、
  `CollectorResponseV1::ok()/error()`、`record_from_v1()`；round-trip 测试断言域↔线格式
  逐字节无损（含 >2⁵³ 大整数与 >1e12 USD 的 nano 成本）。

## 完整 Agent 清单（registry 审计）

来源：vendored `BUILT_IN_AGENT_NAMES`（17 个，含 PR #1487 移植的 antigravity）× 产品支持范围
（v0.2 unified sidecar 对任意 agent id 通用）。CAM `AgentKind::ALL` 与之一一对应，
`AgentKind::from_id()` 提供未知 id 的类型化拒绝：

claude, codex, opencode, amp, droid, codebuff, hermes, pi, goose, openclaw, kilo, copilot,
gemini, kimi, qwen, grok, antigravity（共 17）。

同一数据不会重复统计：每个 agent 在 unified registry 中恰好注册一次；per-agent 采集各自
只读自己的 registry 条目（契约测试 `antigravity_and_claude_do_not_double_count_the_same_data`
与 `six_agents_collect_independently_without_cross_talk` 验证）。

## golden parity

`tests/golden/<case>/`：input 为合成脱敏 fixture，`expected.json` 为已审计的
`CollectorResponseV1` 精确文本；测试失败时 FAIL 并打印 diff，**绝不自动覆盖期望文件**。

| 用例 | 输入要点 | 审计要点（数值来源） |
| --- | --- | --- |
| claude-basic | 两日各一条记录，log 内 costUSD 0.01/0.125 | cost 取 log 值（Auto 模式）：10_000_000 / 125_000_000 nano；tokens 160/338 |
| codex-basic | 两日 gpt-5.2 token_count 事件 | 定价 $1.75/$0.175(cache)/$14 per M：日1 cost 900×1.75+100×0.175+200×14 = 0.0043925 USD = 4_392_500 nano ✓；日2 1_916_250 nano ✓；codex `total_tokens` 为 agent 自报总量（含 cached 与 reasoning，900+100+200+20=1320），桶之和≠total 是 codex 原生语义 |
| antigravity-basic | 测试内以审计过的 protobuf 编码器建库（参数见 README） | 定价 $2/$0.2/$12 per M：(7321×2+10×0.2+604×12)/1e6 = 0.021892 USD = 21_892_000 nano ✓ |
| claude-corrupt | 一条有效记录 + 非法 JSON 行（含 usage 标记）+ 非 usage 行 | 有效记录保留；非法 JSON 行 → `corrupt_record` 诊断；无 usage 标记的行是合法非记录，不算损坏 |

与 v0.2 sidecar 的关系：v0.2 通过同一 ccusage 生态的 sidecar 输出同一 `daily --json --by-agent`
报告；上述数值全部按 models.dev/LiteLLM 快照定价表手工复核（命令与公式见各用例注释）。
npm sidecar 与 vendored Rust 引擎的逐字段自动 parity 需要真实 sidecar 可执行文件，无法在
禁网测试内运行 —— 该对照属 Phase 1 验收的 shadow 对照步骤（计划 Phase 4），在真机上以
`pnpm fetch:sidecar` 暂存 sidecar 后执行，不在本任务内伪造。

## 已知限制（Phase 2/3 前置事项）

当前仍使用 sidecar 作为生产采集路径。切换前必须完成：

1. **会话级记录**：`UsageRecord` 是日聚合；session 明细与 `CollectorRequestV1/ResponseV1`
   的 worker 传输在 Phase 2 实现（协议本身已就绪并测试）。
2. **worker 进程模型**：自身 EXE worker、监督/超时/取消（`Timeout`/`Cancelled` 错误路径）
   属 Phase 3。
3. **数据根路径枚举**：`DataSource::Environment` 依赖 vendor 按环境变量解析；worker 若需要
   "只采 Claude" 也应显式传 `Paths`（已支持）或由 vendor 暴露根路径枚举 API（可选优化）。
4. **npm sidecar shadow 对照**（上文 golden parity 节）：真机一次性执行并记录，属验收步骤。
5. **性能化**：`single_thread` 当前强制；并行加载属 Phase 4 测量后的决策。
