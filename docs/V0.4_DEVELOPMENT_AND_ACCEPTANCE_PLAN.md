## 2. 当前基线：事实与尚未交付项

### 2.1 已核实事实

1. [事实] `v0.3.0` 已于 2026-09-01 发布；当前 `package.json`、
   `src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json` 均仍为 `0.3.0`。
2. [事实] 当前生产采集由 Rust 通过 `current_exe()` 启动同一产品 EXE 的隔离 worker；
   一次生产请求覆盖注册表中的 17 个 Agent。不存在外部 ccusage sidecar 生产回退。
3. [事实] worker 监督保留超时、取消、kill/wait、退出门禁；全量刷新使用 single-flight，
   成功和失败结果均短暂缓存 2 秒。托盘后台刷新间隔当前为 5 分钟。
4. [事实] `normalize_snapshot` 遇到任一 Agent 的结构化错误时返回整次刷新失败，不发布
   部分 `UsageSummary`。成功 Agent 内的可恢复诊断可随 collector 内部协议传播，但当前
   CAM 公共 `UsageSummary` 不向 UI 表达这些诊断。
5. [事实] 当前 Rust/TypeScript 公共契约形状一致：`UsageSummary` 只有成功采集时间、
   今日聚合和最近七日；日级数据包含六类 Token、可空成本、可空缓存输入占比和动态
   Agent/模型明细。公共契约不含刷新尝试、失败状态、统计完整性、语言偏好或缓存来源。
6. [事实] 当前成本规则把无用量或任一贡献模型缺价的日级成本表示为 `null`；真实数值
   `0` 与 `null` 在类型上可区分。六类 Token 的加总和 JavaScript 安全整数边界由 Rust
   adapter 负责。
7. [事实] 当前 React 在内存中保留最后成功快照；首次失败进入错误状态，后续失败把旧
   快照标为 stale。托盘刷新失败时保留旧文本并直接返回，尚不展示失败尝试、数据日期或
   统一新鲜度状态。
8. [事实] 应用 SQLite 目前只初始化 `usage-cache.sqlite3` 及连接设置，没有 CAM 用量
   业务表；当前没有跨重启的最后成功聚合快照。
9. [事实] 当前窗口只有一个主窗口，无路由和侧边栏；配置尺寸为最小 `420×560`、默认
   `680×700`。
10. [事实] v0.3 对外支持范围仍是 Windows 11 x64 only、unsigned、完整非 ASCII 用户
    目录 GUI 未验证。相关三项 waiver 是 2026-09-01 的历史发布决定，本计划不修改它们。

公共契约基线：[TypeScript](../src/types/usage.ts) 与
[Rust](../src-tauri/src/usage/mod.rs)。以上代码核对用于规划，不等同于本轮产品测试。

## 3. 本轮不可越过的范围与三项策略

### 3.1 共同范围

- [策略] 继续保持 Windows、本地优先、单窗口、无路由/侧边栏；React 只消费 CAM
  公共契约，Rust 负责采集、文件、缓存、偏好、原生窗口和托盘职责。
- [策略] 保留 `current_exe()` 隔离 worker、single-flight、超时、取消和退出清理；
  不恢复外部 sidecar，不让 vendored JSON、vendor 类型或原始错误进入前端。
- [策略] Rust/TypeScript 公共契约发生变化时必须同步并有序列化/解析测试。未知值不能
  伪造为零，失败来源不能静默当作零，fixture 或 mock 不得展示成真实用量。
- [策略] 运行时统计继续默认离线；不加入遥测、云同步、更多 Agent、通用插件框架、
  默认联网、自动发布或无必要依赖。
- [策略] 不读取或公开真实日志、凭据、对话、数据库、个人路径或真实用量截图；优先用
  隔离 fixture、可控时钟和测试替身。
- [策略] 本计划不自动 bump 版本、打 tag、推送、创建远程 PR、发布或上传资产；不改变
  AGENTS.md 的范围约束和任何旧验收或 waiver。

### 3.2 三项关键策略

1. **全量失败策略不变。** 本轮保留“任一结构化 Agent 失败导致整次刷新失败”。诊断和
   状态透明化用于解释失败或不完整覆盖，不代表允许发布无标注的部分总量，也不允许拼接
   不同采集时间的 Agent 快照。成功 Agent 内存在跳过记录时，可以保留已接受数据，但
   必须把统计完整性明确标为可能不完整。
2. **单窗口主体验优先。** 托盘任务只增强现有托盘菜单、tooltip 和主窗口入口；不创建
   独立托盘浮窗、桌面悬浮窗、任务栏嵌入组件、第二主窗口或设置路由。
3. **只允许最小恢复缓存。** 为跨重启保留最后成功的 CAM 聚合快照可以增加一个有界、
   版本化的最小缓存。完整历史数据库、会话/项目/逐消息表、增量索引、文件监听器和常驻
   worker 均不提前建设。T07 若获授权，先按需重算和有界结果缓存。

## 4. 统一语义

字段名、envelope 拆分和存储格式由实际任务在最小设计中确定；本节先固定用户可观察语义，
不为未激活候选功能提前扩充生产契约。

### 4.1 新鲜度与刷新状态

- `成功采集时间` 是产生当前聚合快照的完成时间；读取内存或磁盘缓存不得重写它。
- `最后尝试时间/结果` 描述最近一次刷新尝试，与成功采集时间分开。刷新中继续展示可用
  快照；失败后保留最后成功快照并显示失败，首次从未成功则显示可恢复错误。
- 以当前 5 分钟后台周期为基线：成功快照与当前本地日期/时区一致，且成功时间距当前不
  超过 10 分钟时为“新鲜”。10 分钟给正常周期一次延迟/重试余量；T01 若用实测改变刷新
  周期，必须先同步修订该阈值及理由。
- “最近一次刷新失败”和“快照已过期”是可同时存在但不同的状态。一次失败不会自动把
  仍在 10 分钟窗口内的快照改写成旧数据；超过阈值、日期/时区不匹配或时间戳在未来且
  无法可信比较时才标为旧/新鲜度未知，并触发安全刷新。
- 命令、初始化状态和事件必须携带足够身份来拒绝迟到结果。较旧的成功、失败或范围响应
  不得覆盖较新的状态。

### 4.2 跨日与时区

- “今日”按发起采集时的 Windows 本地时区和本地日历日计算；生产七日范围为
  `today - 6 ... today`，两端包含，共七个升序日桶。
- 快照必须保留它所代表的数据日期/范围和时区语义。跨午夜、系统从睡眠恢复或本地时区
  改变后，旧快照只能按其原日期显示，不得继续标为“今日”；应用应请求当前范围刷新。
- 迟到的前一日期/旧时区响应不得覆盖新日期/新时区状态。缓存时区与当前统计时区不一致
  时只可作为明确标注的历史旧快照，或安全废弃后重新采集，不能混算。
- 成功的完整采集可对范围内无记录日期补零。采集失败不能用补零生成“成功”日；来源失败
  也不能伪装成零。

### 4.3 统计完整性与来源状态

- **完整且有数据：** 所有结构化 Agent 结果成功，且没有表明记录/文件/数据库被跳过的
  诊断；数值可按正常聚合展示。
- **完整但为零/空：** 所有结构化 Agent 结果成功、无不完整诊断，选定范围内没有用量；
  这是有效零，不等于“Agent 未安装”。没有来源、没有记录和未安装只有在采集层有确切
  证据时才能区分。
- **成功但覆盖可能不完整：** Agent 结果整体成功，但有损坏文件/记录、数据库不可读、
  来源变化或不变量等跳过诊断。可展示已接受记录的总量，但必须在主界面相关位置明确
  标注覆盖风险；无法定位日期时按整个快照范围标注。
- **整次失败：** 任一结构化 Agent 错误、协议错误、超时、取消或公共不变量失败。不得发布
  本次部分聚合；若有旧成功快照则保留并显示失败，否则显示首次错误。
- 面向用户的诊断只能是稳定类别、受影响来源的安全显示名和可行动提示；不含原始日志、
  SQL、对话、凭据或绝对路径。前端不得通过解析错误字符串推断类别。

### 4.4 成本未知

- `estimatedCostUsd = null` 继续表示没有可作为完整估算展示的数值。无用量造成的“不适用”
  与有用量但缺价造成的“无法完整估算”须结合统计/用量状态显示成不同文案，不能都渲染为
  `$0.00`。
- 数值 `0` 只表示存在可计算范围且完整计算结果确为零。任何贡献模型缺价时，总成本保持
  未知；不得把已定价部分冒充完整总额。
- 成本始终是 vendored 离线价格快照下的 API 参考估算，不是账单、订阅费用、credits 或
  Claude/Codex 账户额度。若公开价格快照版本/日期，必须来自真实构建元数据。
- 候选 T10 若以后展示已定价部分小计，必须单独标注覆盖，不改变本节的完整总额规则。

### 4.5 语言偏好

- 支持的轻量语言集合为简体中文和英文；默认偏好为 `system`，在应用启动时从 Windows
  系统语言解析，不支持的系统语言回退英文。主界面、托盘、状态、日期和辅助技术标签在
  同一时刻使用同一个已解析语言。
- T03 建立轻量字典与共同解析边界；若提供显式选择，T05 仅持久化 `system / zh-CN / en`
  这类最小偏好。损坏或未知值回退 `system`，不阻止应用启动。
- Agent 名、开放 Agent ID、model ID 和其他动态用户数据不翻译。数字与日期按已解析语言
  格式化，但 Token、USD 等单位和精确数值语义不改变。
- 不建立语言路由、下载语言包或大型 i18n 框架；是否支持运行中即时切换由 T03/T05 的最小
  实现决定，但窗口与托盘必须保持一致。

### 4.6 历史范围

- 核心 T01–T06 只保证当前七日范围：包含今日和之前六个本地日；今日摘要不受趋势 Agent
  筛选影响。
- [候选] T07 获单独授权后可增加按需 30 日范围：包含今日和之前 29 个本地日。托盘和常规
  后台刷新仍只承担轻量今日/七日请求；30 日不能默认加入后台采集。
- 范围身份至少在语义上包含起止日、时区、来源/协议版本；不同范围的 flight、短缓存、
  持久缓存和迟到响应不能串用。所选日期必须属于当前可见范围，范围或刷新变化后按确定性
  规则保留或清除选择。
- 缺日补零只表示一次成功查询在该日本地日桶无记录，不证明 Agent 未安装；异常日和范围
  级完整性必须继续可见。

## 6. 核心任务定义

### 6.1 T01 — 统一采集状态、托盘新鲜度与跨日行为

**目标 [已实施]**

- 让命令、事件、主界面和托盘共享最后成功快照、最后尝试结果、刷新中状态、数据日期和
  新鲜度语义；首次打开不依赖曾经错过的事件。
- 修复首次/手动/定时/焦点刷新、迟到响应、跨午夜和睡眠恢复中的状态竞态；失败时保留
  可用数字但不冒充最新数据。

**非目标**

- 不实现跨重启持久化、部分 Agent 拼接、系统通知、提高轮询频率或重构采集引擎。
- 不改变完整结构化 Agent 错误导致整次失败的规则。

**依赖：** T00 已完成；用户已单独发送并授权 T01 Prompt。

**契约影响：** 实际采用最小 `UsageCollectionState` envelope，由 Rust 命令和事件统一
提供；`UsageSummary` 的 Token/成本聚合语义保持不变。Rust/TypeScript 已同批同步；原始
`AppError`、路径或 vendor diagnostic 不进入前端。

**实际验收方式：** 使用可控时钟和隔离 worker 替身覆盖首次成功/失败、手动和定时失败、
重试成功、连续点击、状态读取与事件注册竞态、迟到结果、事件卸载、跨日、时区变化和睡眠
恢复；Rust 测试验证 single-flight、2 秒短缓存、全量失败和退出取消仍成立；前端 unit/E2E
验证旧数据、刷新中和错误显示；在 Windows 原生托盘实际核对主界面/托盘日期与成功时间。

**停止条件：** 发现 T00 基线不成立；最小统一状态无法在不泄露敏感错误或不破坏

### 6.2 T02 — 统计口径、成本未知与来源诊断透明化

**非目标**

**实际验收方式：** collector/protocol/adapter 契约测试覆盖已知真零、无用量、完全缺价、混合
缺价、成功带诊断、损坏/跳过记录、未知 Agent、结构化 Agent 致命错误和超大整数；UI 测试

**停止条件：** 采集层没有证据支持拟展示的来源状态；只能通过发布部分总量或前端解析原始
错误实现；需要读取真实凭据/日志才能验证；发现 token/成本不变量无法保持。记录差距，不编造
状态，不提前实施 T03/T10。

不提前实施 T07。

### 9.1 后续实现任务的检查选择

| 改动范围 | 最少检查 |
| --- | --- |
| 任一文档 | 链接/状态一致性、`git diff --check` |

执行者必须先核对脚本仍存在。命令未运行、被环境阻断或只覆盖浏览器模拟时如实记录，不能

### 9.2 核心链完成定义

T01–T06 只有在各自依赖、目标、契约同步、任务特定验收和共同矩阵适用项都有当前基线证据
后，才可将对应状态更新为完成。某个原生场景 `NOT RUN` 是否阻断任务完成，须按该任务 Prompt
和风险明确判断；执行代理不能自行批准 waiver。核心链完成也不自动激活 T07–T10，不等于
v0.4 release candidate，更不授权版本 bump、发布或上传。

## 10. 已知风险与下游注意事项

1. 当前公共契约只表达成功快照；T01 与 T02 必须协调状态 envelope 和完整性元数据，避免
