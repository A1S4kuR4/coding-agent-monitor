### MSI per-user install failure and recovery (2026-09-25)

The v0.5.1 MSI built from `cd3f5313004fc4da6370091b1087dd7908b9c697`
was invoked with `msiexec /i`, `ALLUSERS=2`, `MSIINSTALLPERUSER=1`,
`INSTALLDIR=D:\DevTools\cam-v051-upgrade-test`, `/qn` and `/norestart`.
The installer returned exit 0, but AppSearch/remembered-path behavior overrode
the requested directory. It wrote into `D:\DevTools\test\Coding Agent Monitor`,
which contained four orphan files before the attempt, and registered the
product under HKLM rather than the expected HKCU. The HKCU remembered-path
value remained `D:\DevTools\cam-v051-upgrade-test`. The controlled path and
per-user registration gate is **FAIL**, regardless of the process exit code.

The installed 0.5.1 worker smoke passed as recorded above. Uninstallation
returned exit 0 and left zero CAM uninstall registrations under either HKLM or
HKCU. The four original files were restored from pre-test backups and verified
byte-for-byte by SHA-256; the restored original EXE hash was
`63114B49633BA16B34D329B0CF287AA220C5096FCD3222C6376F55C1BE0AEA15`.
This recovery is evidence about the test host, not a passing MSI install gate.
Because the path and privilege scope were unexpected, the MSI
v0.5.0→v0.5.1 upgrade was not attempted.
