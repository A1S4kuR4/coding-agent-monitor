## 1. 早期入口顺序（`src/main.rs`）

```
进程启动
 ├─ argv[1] == "--cam-internal-collector-worker-v1" ?
 │   └─ 是 → worker::run_worker_stdio() → exit(code)   ← 任何 Tauri/DB/托盘/刷新
 │                                                      /sidecar 初始化都不会执行
 └─ 否 → coding_agent_monitor_lib::run()               ← 正常 UI/托盘路径
```

- flag 在所有初始化之前识别；worker 模式**不初始化** WebView2、Tauri Builder、单实例插件、
  窗口/托盘、CAM 应用 DB、定时刷新、sidecar runner（集成测试以重定向 APPDATA 后无
  `usage-cache.sqlite3` 证明）。
- worker 模式不 spawn 自身、ccusage、shell 或任何子进程（worker 模块无 Command 调用，构造上排除）。
- 携带 flag 的进程永远不会再进入可 spawn worker 的父路径 → 递归构造性阻止（双重 flag 测试锁定）。
- 该 flag 为内部实现：不出现在帮助页，不是公开 CLI 承诺；worker 不是安全权限边界。

## 2. Worker 状态机

```
run_worker_stdio:
  1. 设置 worker-only 静默 panic hook（不影响 Tauri 模式——worker 入口先于一切）
  2. [debug/test 构建] 注入钩子（CAM_TEST_WORKER_*；release 构建完全编译剔除）
  3. 读 stdin 至 EOF，硬上限 256 KiB（超限立即停止累积）
  4. catch_unwind { handle_request_bytes }：
       a. 长度门禁（256 KiB）
       b. UTF-8 校验（错误信息脱敏：仅偏移+长度，不含字节内容）
       c. serde 解析（严格一个 JSON 文档；尾随内容=错误）
       d. into_domain：版本门禁 → agent/日期/roots/时区上限校验
       e. AgentCollector::collect 一次
       f. 构造 CollectorResponseV1（成功或结构化错误）
  5. 响应序列化；>16 MiB 时替换为结构化 Internal 错误
  6. 一次性 write_all + flush 到 stdout；exit 0
  7. 任何 panic → 结构化 Internal 错误响应（无 panic 文本）→ exit 0；仅当连响应都无法写出
     时才非零退出
```

## 3. stdin/stdout envelope 与字节上限

| 通道 | 上限 | 理由 |
| --- | --- | --- |
| stdin | 256 KiB | V1 请求上界：16 roots × 4 KiB 路径 + envelope ≪ 128 KiB，256 KiB 留余量 |
| stdout | 16 MiB | 单 agent 日聚合响应通常数 KiB；16 MiB 容纳极端多年历史 |
| stderr（父进程读取上限） | 64 KiB | 诊断 debug 文本上限；超出截断，防管道满死锁 |

- stdin 只允许一个完整 JSON request 至 EOF；尾随空白容忍，第二个 JSON 或其他尾随内容拒绝；
  非 UTF-8 拒绝（脱敏错误）。
- 不通过 argv 传递日期/路径/JSON（防 quoting/injection）。
- stdout 在内存中完整构造后一次写出；request_id 与输入一致。
- 错误响应：结构化 code、agent/vendor 归属、脱敏 message；无绝对路径、SQL、原始记录、
  session、prompt、调用栈。
- 正常 stdout 零杂音；diagnostic log 只写 stderr（vendor `debug_log` 通道），父进程有界读取
  后**丢弃**——不进 React、不持久化。

## 4. 错误映射（supervisor）

| 父进程观测 | CollectorError |
| --- | --- |
| spawn 失败（exe 缺失/权限） | `Internal` |
| stdin 写失败（broken pipe 等） | `Protocol` |
| 超时（默认 120 s，可注入） | `Timeout`（child kill+wait） |
| cancel / 应用 shutdown | `Cancelled`（child kill+wait） |
| 非零退出（含 worker 未捕获 panic，exit 101） | `Internal`（不含 panic 原文） |
| stdout 空 / 超 16 MiB / 非 UTF-8 | `Internal` / `Protocol` / `Protocol` |
| JSON/version/request_id 校验失败 | `Protocol` |
| 响应内结构化错误 | 原样重建的 `CollectorError`（归属/分类保留） |

## 5. timeout / cancel / 回收

- supervisor 等待循环每 10 ms `try_wait`，同时检查 cancel 标志与应用 shutdown 标志
  （`sidecar::is_shutting_down()`，与 sidecar 共用同一门禁）。
- 超时/取消路径显式 `kill()` + `wait()` 并 join 两个读取线程——**不依赖 Drop 异步语义**；
  所有路径最终 wait/reap，无 zombie、无残留句柄。
- shutdown 门禁生效后拒绝启动新 worker（返回 `Cancelled`）。
- Windows：worker 以 `CREATE_NO_WINDOW` (0x0800_0000) 启动，无控制台窗口；worker 不产生
  孙进程（worker 模块无 spawn），故无需 Job Object——直接 child 的 kill+wait 覆盖全部路径。
- 不使用 taskkill/shell 启动或终止正常 worker。

## 6. single-flight（`worker_runner`，语义对齐 sidecar runner）

- 同一刷新窗口最多一个 worker flight；20 个并发调用共享同一成功/失败结果（spawn-marker
  计数测试证明恰好 1 个 worker 进程）。
- 成功与失败都缓存 2 s（`RESULT_FRESH_FOR`，与 sidecar 相同）——失败也不被紧循环重启。
- 调用者不单独取消；应用 shutdown 取消整个飞行中采集，所有等待者得到 `Cancelled`。
- panic/timeout/协议错误都会解析 flight 并清空槽位——状态不会卡死，后续刷新恢复。

## 7. SQLite immutable 竞态处置（Phase 2 遗留，本阶段关闭）

`adapter-common::load_source_db_stable`（0002 patch）：

1. 读取前快照：主 DB 大小/mtime + `-wal`/`-shm` 存在性与元数据；
2. 无 sidecar → `immutable=1` 快速路径执行读取；
3. 读取后复核快照：**任何变化（sidecar 出现、大小/mtime 移动）→ 丢弃 immutable 结果**；
4. 回退：普通 READONLY 连接 + `BEGIN`/`COMMIT` 读事务（单一一致性快照，即使 agent 持续
   写入也不少计），**最多一次重试、无循环**；
5. 回退读取期间源仍在变 → 结果（一致性快照）照常返回，但报告 `SourceChanged` 结构化
   diagnostic——绝不静默成功，也绝不返回可能少计的 immutable 结果；
6. 采集全程只读：不创建/修改源 DB、WAL、SHM、journal（Phase 2 完整性测试保持通过）；
7. 通道同步的确定性竞态测试（`stable_source_tests`）：闭包内在读取中途打开 WAL writer 提交
   新行——immutable 结果被丢弃、回退读到已提交行（1→2）；无竞态时 `Stable`；plain 路径
   在活跃写入下返回一致性快照。无随机 sleep。

## 8. 测试矩阵（`tests/worker_integration.rs`，产品 EXE 实测）

- **Worker 入口**：claude fixture 端到端；antigravity 空=成功；collector error→结构化错误
  （SourceUnavailable 归属保留）；malformed JSON/尾随第二 JSON/非 UTF-8→Protocol；错误版本/
  未知 agent/空 roots→InvalidRequest；超长 stdin→Protocol limit；stdout 恰好一个 JSON 文档；
  worker 不初始化应用 DB（重定向 APPDATA 断言）；双重 flag 不递归。
- **监督路径**：success round-trip；非零退出→Internal；panic→Internal 且无 panic 文本泄漏；
  garbage stdout→Protocol；stderr flood 不死锁（有界时间）；timeout→`Timeout` 且 kill（<10 s
  实测）；cancel→`Cancelled` 且 kill；连续失败后恢复；20 并发共享 1 个 worker（spawn-marker）；
  失败共享且不卡死。
- **SQLite 竞态**：见 §7（vendor `stable_source_tests` 3 项，通道同步）。

## 9. 安全与隐私边界

- worker stderr 有界读取后**丢弃**：不进 UI、不进应用 DB、不进日志文件。
- panic 文本/backtrace 不进入任何响应（worker 内静默 hook + 父进程仅报告 exit code）。
- 协议 JSON 全部走中央脱敏（Phase 1 机制）：无绝对路径、SQL、原始记录、session、prompt。
- worker 与父进程同特权、同用户；不是安全边界，进程间无权限校验。
